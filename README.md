# 应用宝后台积分任务

适用于应用宝 `com.tencent.android.qqdownloader` 的 LSPosed 模块。控制界面会在受信任的隐藏显示中启动应用宝，串行完成当前可领取的两组视频任务。广告由应用宝实际加载和播放；模块在真实奖励回调后关闭广告并等待应用宝确认积分到账，再继续下一条。模块不会伪造观看时长、奖励回调或完成请求。

## 安装与作用域

1. 安装发布页的 APK，在 LSPosed 中启用模块。
2. 勾选模块推荐的两个作用域：**系统框架**（`android`）和 **应用宝**（`com.tencent.android.qqdownloader`）。APK 的 `xposedscope` 元数据包含这两个包名。
3. 重启手机，然后在模块应用中点击“开始后台观看”。不需要预先打开应用宝；应用宝账号需已登录。

也可以在模块应用中开启“每日定时”并选择本地时间。默认关闭；首次启用时，Android 12 及更新版本可能要求在系统页面允许“闹钟和提醒”。授权后每天重新登记下一次闹钟，重启或系统时间变化后重新计算。未授权时控制页显示等待授权，定时任务不会错误地显示为已安排。定时触发会从后台唤醒应用宝，不要求提前打开控制界面。系统仍可能将闹钟延后数十秒。

旧测试包 `com.codex.yybpoints` 与本发布包 `io.github.ahdaolma.yybpoints` 是两个不同应用。迁移时先在旧包内停止后台播放并确认隐藏显示已释放，再于 LSPosed 中停用旧包、卸载旧包，启用新包并重启。卸载前可使用应用内的“清理并卸载模块”；系统卸载会删除模块私有数据。完整卸载后重新安装时，需在 LSPosed 中重新启用模块并勾选两个作用域，然后重启手机。

## 功能

- 同时检查滑动视频与白卡视频两组任务，**串行**播放有资格领取的任务。应用宝广告管理器一次只接受一条广告。
- 检测真实奖励回调后尝试关闭广告；有“再看一条”弹窗时使用应用宝原生动作继续。播放期间阻止批量任务重复启动。
- 控制界面显示当前账号、头像、本轮任务和已核对积分。每条任务的到账金额优先读取应用宝领取成功回执中的 `receivedPoint`；未登录时提示登录，金额无法核对的记录不计入合计。
- 控制界面跟随 Android 系统深浅色模式，状态栏、定时弹窗和操作控件一并切换。开始和停止共用底部主按钮，切换后短暂锁定，避免连续误触；系统框架回执按本轮请求编号匹配。
- 本轮有领奖记录时，在自然结束或手动停止后显示开始至结束的日期时间、总积分和按金额汇总；已核对的逐条积分可展开查看。0 条任务不生成总结。
- 有领奖记录的定时与手动运行都会保留最近 14 轮历史总结，包含每条已核对积分。两种运行方式均显示模块应用的常驻通知，通知可在锁屏显示“视频任务正在运行”；结束后移除常驻通知并发送结果通知。通知由模块应用自己的权限发送，不使用系统框架身份。Android 13 及更新版本首次打开控制页时，由模块直接调用系统原生通知授权弹窗，不显示应用内开启指引。若用户拒绝通知，任务仍可运行，控制页保存上次结果。
- 后台任务运行时，在应用宝进程内拦截其音频焦点请求并将其播放音量设为零，避免系统音量被改变。停止时释放隐藏显示并结束应用宝进程。
- 后台批量观看期间抑制应用宝进程的系统 Toast，避免提示文字显示在手机主屏幕；任务状态仍显示在模块控制界面。
- 手动和定时运行均由服务持有有界 CPU 唤醒锁，上限 43 分钟；运行 42 分钟后主动停止，系统框架中的隐藏显示另有 45 分钟到期清理保护。隐藏显示使用独立显示组，实体屏幕熄灭后仍可保持 ON。正常完成、手动停止、任务页加载失败时都会移除隐藏显示；系统端会在短时间内复查并结束可能被未完成的内容提供者请求重新拉起的应用宝进程，确认后才报告停止成功。模块进程意外死亡时，系统端通过 Binder 死亡通知执行相同清理。系统进程异常或手机重启时，Android 自身会释放虚拟显示。
- 仅对应用宝已经明确返回失败的领取请求提供补领入口；成功或状态不明的请求不重复提交。

应用内“清理并卸载模块”会在无需清理后台会话时直接打开 Android 系统卸载确认页；有会话时先请求停止，再打开确认页。若系统未确认清理，控制界面会提示重启手机。确认卸载后，模块私有数据由 Android 删除。已有应用宝任务栈无法迁移时，模块会结束旧进程并在隐藏显示重新启动应用宝。

## 性能与验证范围

发布包不安装协议和网络诊断钩子；这些钩子仅供调试包排查问题。头像先读取图片尺寸并采样解码，再生成 128×128 圆形头像。隐藏显示为 180×320 像素，使用两个图像缓冲区。

2026-09-28 在一台真机的**空闲状态**测得旧调试包控制进程约 23 MB PSS，处于系统可回收的缓存空进程；应用宝主进程及两个子进程合计约 424 MB PSS。此数据不是新发布包或广告播放时的内存峰值，不应据此声称内存下降了某个数值。

在应用宝 9.1.4 和同一真机上验证过隐藏显示创建、应用宝启动、两组任务识别、真实奖励回调与到账、连续观看、结束清理。音频隔离通过隐藏显示内的焦点请求探针验证。已从该版本动态任务包确认成功领取回执中 `y.l0.c.a` 是任务页采用的 `receivedPoint`，并通过独立解析测试。2026-09-28 用 ADB 真机复测：已打开的应用宝主任务栈可迁移到隐藏显示；两组任务均为 `canReceive:0` 时，本轮 0 条不生成总结，结束后隐藏显示和应用宝进程均清理；应用内卸载按钮可打开正确包名的系统卸载确认页。首次定时验证时，闹钟在控制页关闭后触发并创建隐藏显示，但冷启动的应用宝任务页未在旧等待时间内加载；随后正常移除了隐藏显示并结束应用宝进程。延长等待时间后复测，定时运行在控制页关闭时成功进入任务页并识别两组任务，因当时均为 `canReceive:0` 而自然结束，隐藏显示和应用宝进程均清理。Android 16 真机上全新安装的临时包以 target SDK 33 首次打开时显示了系统原生通知授权弹窗；target SDK 28、32 在同机没有弹窗，临时包随后卸载。target SDK 33 的正式包在系统授予精确闹钟权限后从后台触发了定时任务，结束时发布模块应用的结果通知，隐藏显示与应用宝进程被清理；音频焦点保持在原前台应用。测试闹钟已关闭。**真实广告下的定时领奖和历史总结仍需复测**。

0.3.0 在同机验证了系统浅色与暗色界面，系统主题切换后状态栏和控制页颜色同步变化。连续快速点击开始键只创建一个隐藏显示；随后点击停止，系统确认移除显示并结束应用宝进程，检查时没有残留的应用宝进程或隐藏显示。该轮在任务启动阶段主动停止，未验证实际广告奖励。

0.3.1 发布包在同一 Android 16 真机上复现了旧版息屏后隐藏显示变为 OFF；改为独立显示组后，实体屏幕进入 Dozing 时隐藏显示保持 ON，任务数据轮询继续进行。定时闹钟在息屏后唤醒服务、启动隐藏显示并进入应用宝任务页；当天两组任务均无可领取项，因此自然结束后无广告领奖可核验。停止时发现应用宝内容提供者请求会在第一次结束进程后再次拉起进程；改为延后复查后，停止确认再过 8 秒仍无应用宝进程、隐藏显示、CPU 唤醒锁或运行通知。强制结束模块进程曾导致显示与应用宝残留；加入 Binder 死亡清理和有界清理唤醒锁后，在主屏熄灭时强制结束模块进程，8 秒后的检查同样没有上述残留。成功回执金额解析增加字段名变化与单元素列表的兼容；由于当天没有新任务，25/35 等金额的真机回归仍未完成。

2026-09-29 用 ADB 在运行中执行保留数据的用户卸载，8 秒后未检出隐藏显示、应用宝或模块进程、相关唤醒锁和运行通知，重新启用该用户后原有设置仍在。随后执行不保留数据的完整卸载，8 秒后包和包路径不存在，系统框架的命令接收端、隐藏显示、应用宝与模块进程、相关唤醒锁、模块通知及定时闹钟均未检出。重新安装并重启后，应用数据目录已重建，LSPosed 命令接收端尚未注册；重新启用模块作用域并再次重启后接收端恢复。上述检查验证了当次运行资源与安装状态，不能证明系统缓存绝无任何残留。

## 构建

使用 JDK 17、Android SDK 34 和 Gradle wrapper：

```powershell
.\gradlew.bat assembleDebug
```

正式包使用 `tools/build-release.ps1`。脚本从当前 Windows 用户的 `.android/yybpoints-ahdaolma-signing.json` 读取签名配置，私钥和密码均不在仓库中。保管好签名密钥及密码；后续同包名更新必须使用同一密钥。

诊断日志：`adb logcat -s YybPointsProbe:I YYBBackground:I`。调试包有受 `android.permission.DUMP` 保护的 ADB 诊断入口；发布包不含该入口。
